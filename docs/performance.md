# 性能と測定方法

[README に戻る](../README.md)

ここに掲載するのは、2026-11-04〜2026-11-06 に記録した測定結果です。現在のリリースや別の PC で同じ性能を保証する値ではありません。導入と構成の選び方は [README](../README.md)、ツールとテストの前提は [開発ガイド](development.md) を参照してください。

測定機は Windows 11、Ryzen 9 9900X、RTX 5090（32 GB）です。ASR 比較時の主なソフトウェアの記録は faster-whisper 1.2.1、CTranslate2 4.8.5、torch 2.14.1+cu130、transformers 5.22.1 です。モデルのリビジョン、ドライバ、全依存パッケージを含む完全な再現条件を示すものではありません。

## ASR の認識精度と処理速度（2026-11-04）

`tools/asr_bench.py` で、各クリップを Silero VAD v6 により発話単位に分割しました。無音 500 ms、最大 15 秒で区切り、発話ごとに greedy で認識し、言語は自動判定です。GPU 比較では Whisper は float16、Qwen3-ASR は bfloat16 を使う構成です。

日中韓は文字誤り率（CER）、それ以外は単語誤り率（WER）です。値は比率で、低いほど良く、例えば 0.187 は 18.7 % に相当します。

| 音声（各約 1〜3 分） | Whisper tiny（比較用） | Whisper large-v3-turbo | Qwen3-ASR 0.6B | Qwen3-ASR 1.7B |
|---|---|---|---|---|
| 日本語の雑談・フィラー多め（YODAS2） | 0.501 | 0.187 | 0.250 | 0.185 |
| 日本語の技術解説・英語の製品名あり（YODAS2） | 0.332 | 0.098 | 0.179 | 0.153 |
| 英語の決算説明会・数値多め（Earnings-22） | 0.506 | 0.337 | 0.357 | 0.273 |
| 日本語 / 中国語 / 韓国語の読み上げ（FLEURS） | 0.27 / 0.38 / 0.30 | 0.030 / 0.023 / 0.127 | 0.089 / 0.017 / 0.142 | 0.030 / 0.023 / 0.139 |
| フランス語 / スペイン語の読み上げ（FLEURS） | 0.53 / 0.13 | 0.074 / 0.031 | 0.049 / 0.031 | 0.062 / 0.031 |

| GPU での処理 | Whisper tiny | Whisper large-v3-turbo | Qwen3-ASR 0.6B | Qwen3-ASR 1.7B |
|---|---|---|---|---|
| 1 発話あたりの処理時間 p50 | 0.03〜0.09 秒 | 0.10〜0.14 秒 | 0.4〜1.2 秒 | 0.4〜1.25 秒 |
| 実時間比（RTF） | 0.006 | 0.015 | 0.10 | 0.10 |
| VRAM 増加 | 0.6 GB | 2.3 GB | 2.3 GB | 4.9 GB |
| モデル読み込み | 0.6 秒 | 1.8 秒 | 6.4 秒 | 5.3 秒 |

RTF は処理時間を音声時間で割った値です。ASR の処理時間は、共有ピッカー・通信・VAD の区切り待ち・画面描画を含む最終字幕までの遅延とは異なります。

この比較では、turbo は日本語の 2 クリップで Qwen3-ASR 1.7B と同程度以上の精度で、処理は速く、VRAM 使用量も小さくなりました。Qwen3-ASR 1.7B は英語の決算説明会で最も低い WER でした。turbo は無音・ノイズを VAD なしで渡した試験で 10 文字の誤った出力があり、VAD ありでは 0 文字でした。VAD と幻聴フィルタが必要です。

CPU の別比較では、whisper-small int8 は日本語の雑談 / 技術解説の CER が 0.252 / 0.192、英語の WER が 0.375、RTF が 0.32〜0.42 でした。whisper-medium は 0.209 / 0.133 / 0.332 と精度が上がる一方、RTF は 0.83〜1.20 でした。CPU では精度と実時間処理の余裕を両方見る必要があります。

測定の限界は次のとおりです。

- 各クリップは約 1〜3 分で、用途・話者・音質を広く代表する規模ではありません。
- YODAS2 の字幕は完全な逐語録ではありません。発話と大きく異なる清書字幕だった講義クリップは、精度の集計から除外しました。
- 数字と数詞の表記揺れは正規化していません。英語の数値を単語で出力しやすい Qwen は、内容が同じでも WER で不利になる場合があります。
- モデル名だけで順位を一般化できません。短い発話、専門語、音楽、配信の音質などによって結果は変わります。

## CPU での長時間処理（2026-11-04）

`tools/soak.py` で 48 kHz の音声を実時間で送り、ライブ処理と同じリサンプラー、Silero VAD、ASR ワーカーを通しました。字幕のみのセッションで、要約 LLM は使っていません。CUDA を隠し、プロセスを少数の論理 CPU に固定して、ASR と OpenBLAS のスレッド数を合わせました。

**CPU の固定は並列度を制限するだけです。1 コアの速度は Ryzen 9 9900X のままなので、エントリー PC の実測ではありません。** 10 分の 2 実行は、30 分の実行の最初の 10 分と同時に、別の論理 CPU で動かしました。

| 構成 | 音声 | 字幕数（欠落 / 途切れ） | 発話終了→確定字幕 p50 / p95 / 最大 | ASR 時間 p50 | RTF | ワーキングセット 中央値 / 最大 |
|---|---|---|---|---|---|---|
| small int8、4 論理 CPU（2 コア＋SMT）、4 スレッド | 30 分 | 238（0 / 0） | 3.1 / 6.7 / 12.3 秒 | 2.5 秒 | 0.39 | 510 MiB / 1.0 GiB |
| small int8、2 論理 CPU（1 コア＋SMT）、2 スレッド | 10 分 | 78（0 / 0） | 6.6 / 13.8 / 18.4 秒 | 4.8 秒 | 0.68 | 545 MiB / 1.0 GiB |
| small float32、4 論理 CPU、4 スレッド | 10 分 | 78（0 / 0） | 5.3 / 11.0 / 14.1 秒 | 4.2 秒 | 0.60 | 1.2 GiB / 1.7 GiB |

4 論理 CPU の比較では、int8 は float32 より RTF が 36 %、ワーキングセットが 58 % 小さくなりました。30 分実行の各 10 分のワーキングセット中央値は 524 / 508 / 512 MiB で、継続的な増加は見られませんでした。最大約 1 GiB の山は長い発話の認識中に生じました。

字幕の遅延には、VAD の 600 ms の無音待ちと、前の発話の処理待ちが含まれます。CPU の light 構成は部分字幕を既定で出さないため、長い発話は話し終わってからまとめて表示されます。処理が実時間に追いつかなくなると待ち行列が伸び、上限を超えた古い発話は欠落として報告されます。

この長時間試験は同じクリップを繰り返しており、認識精度の評価には使えません。低価格 CPU・メモリ 8 GB などの実機、さらに長い配信、他アプリと同時利用したときの余裕は別に測定する必要があります。

## 字幕翻訳の比較（2026-11-05）

Yata の翻訳プロンプトを使った限定的な比較です。Qwen は Ollama、PLaMo は llama.cpp b11800 の Vulkan 版で動かしました。PLaMo のモデルは PLaMo 3 Translate 2B Q4_K_M です。

| モデル・実行環境 | GPU | CPU | メモリ・読み込みの記録 |
|---|---|---|---|
| qwen3.6:35b-a3b（Ollama） | 10 行 約 1.4 秒、1 行 0.3〜0.5 秒 | 記録なし | 読み込みで 21.3 GiB |
| qwen3:8b（Ollama） | 10 行 1.6〜2.0 秒 | 10 行 約 60 秒（6.5〜7 tok/s） | 記録なし |
| PLaMo 3 Translate 2B Q4_K_M（llama-server） | 1 行 約 0.07 秒 | 1 行 約 1 秒（24 tok/s） | VRAM 増加 約 1.8 GB、読み込み 3〜6 秒 |

PLaMo の Vulkan 初回処理は約 5.7 秒でした。CPU は 4 スレッドと 12 スレッドで同程度でした。qwen3.6 と併用すると、qwen3.6 だけのときより VRAM が約 1.8 GB 増えました。

### PLaMo 3 Translate 0.8B と 2B（2026-11-06）

同じ条件（llama.cpp の Vulkan 版、1 行ずつ前 2 行を文脈に付ける Yata と同じ呼び方）で、英→日と日→英を各 10 行訳しました。CPU は 4 スレッドです。

| モデル（Q4_K_M） | GPU | CPU | VRAM 増加 |
|---|---|---|---|
| PLaMo 3 Translate 0.8B | 1 行 約 0.05 秒 | 1 行 約 0.35 秒（65〜70 tok/s） | 約 0.75 GB |
| PLaMo 3 Translate 2B | 1 行 約 0.08 秒 | 1 行 約 1.1 秒（22 tok/s） | 約 1.5 GB |

数値は両方とも 20 行すべて保持されました。0.8B は 20 行中 3〜4 行で単位や意味がずれました（「140 ミリ秒」を「140 秒」、「測定した」を「という声がありました」、「2 秒未満のラグ」を「ラグが生じている」など）。2B ではこれらの行は原文どおりでした。20 行の比較なので、品質差の大きさを示すものではありません。

40 行の確認では数値が保持され、行のずれはありませんでしたが、翻訳品質全般を証明する規模ではありません。モデルごとに 1 行処理と複数行処理が異なるため、上の秒数をそのまま一般的な性能順位にはできません。

翻訳専用モデルが構成を軽くするのは、主に要約 LLM を使わずに字幕を翻訳するときです。要約 LLM と併用するとメモリ使用量は増えます。ASR・要約モデル・翻訳モデルが同時に収まるかを確認してください。要約との同時実行、長い配信、CPU のみや小さな GPU、AMD・Intel GPU での実測は、この比較では確認していません。PLaMo の利用条件は [使い方ガイド](usage.md#字幕の翻訳plamo) を参照してください。

## 再計測とデータの扱い

リポジトリのルートで実行します。モデルを用意し、`YATA_MODEL_ROOT` を自分のモデル保存先に設定してください。依存の導入と対応環境は [開発ガイド](development.md) を参照してください。Qwen の extra は CUDA 版 torch に固定されており、現在の対応は Windows・Linux の NVIDIA GPU 構成です。macOS 用の手順ではありません。

```powershell
# ベンチ用データを取得・作成する（外部への接続とダウンロードが発生する）
uv run --group bench python tools/bench_prepare.py

# CPU で ASR を比較する例
uv run python tools/asr_bench.py --engines fw-small-cpu --modes auto

# 対応 GPU と必要なモデル・extra を用意した場合の比較例
uv run python tools/asr_bench.py --engines fw-turbo,qwen-1.7b --modes auto

# CPU の長時間試験
uv run python tools/soak.py --minutes 30 --profile light --cores 4 --cpu-threads 4 --progress
```

データは `bench/data/`、結果は `bench/results/` に作成され、`bench/` は Git の追跡対象外です。`--cores` と `--first-core` は論理 CPU の固定、`--cpu-threads` は ASR スレッド数、`--compute-type` は精度、`--hide-gpu` は CUDA の非表示を指定します。light 構成では GPU 非表示が既定です。

取得スクリプトが記録するデータセットとライセンス識別子は次のとおりです。クリップごとの出典・区間・条件は生成される `bench/data/manifest.json` に残ります。

| データ | スクリプト内のライセンス識別子 |
|---|---|
| YODAS2 ja000（`espnet/yodas2`） | CC-BY-3.0 |
| Earnings-22（`distil-whisper/earnings22`） | CC-BY-SA-4.0 |
| FLEURS（`google/fleurs`） | CC-BY-4.0 |

この表はスクリプトの記録であり、元音源を含む再配布の権利確認を完了したという意味ではありません。利用・共有・再配布の前に、配布元と各素材の条件を確認し、必要な帰属表示等を保持してください。音声や参照字幕を Yata の配布物へ自動的に含めないでください。
