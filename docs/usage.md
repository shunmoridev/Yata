# 使い方ガイド

[README に戻る](../README.md)

起動スクリプトで Yata を起動すると、Chrome か Edge で `http://127.0.0.1:8765/` が開きます。起動したウィンドウは開いたままにし、終わるときは Ctrl+C で止めます。すでに起動しているときにもう一度起動すると、新しく立ち上げずに既存のページを開きます。

## この PC の準備

サイドバーの下にある **この PC の準備** で、モデルの確認と取得をします。選んだ使い方に足りないものがあると、ここに黄色の点が付きます。画面の上には、この PC の CPU・メモリ・NVIDIA GPU（`nvidia-smi` で取得）・モデル保存先の空き容量が表示されます。

### 1. 使い方を選ぶ

- **字幕のみ**：字幕と文字起こしだけを記録します。
- **字幕＋翻訳**：字幕を翻訳専用モデル PLaMo で訳します。要約は作りません。
- **字幕＋要約・翻訳**：ローカル LLM で話題の区切り・要約・全体のまとめを作り、字幕も訳します。
- **話者ラベル**：上の 3 つと組み合わせて、話者を S1、S2… と区別します。

選ぶまでは、この PC に合う使い方を表示します。要約は、要約モデルが音声認識モデルと一緒に GPU に収まる場合だけ勧めます。収まらない場合は「字幕＋翻訳」に「翻訳するなら」と表示します。最初に何か操作すると、その時点の表示が選択として保存されます。ここで選んだ使い方は、新しいセッションの初期値にもなります。

### 2. 必要なものを準備する

選んだ使い方に必要なものが、カードで 1 つずつ表示されます。各カードには、おすすめのモデルとその理由、サイズ、保存先、配布元とライセンスが載っています。

| カード | 内容 |
|---|---|
| 字幕（音声認識） | whisper-large-v3-turbo（GPU 向け）と whisper-small（CPU 向け、int8）。選んだモデルを次の共有から使います |
| 音声区間の検出 | faster-whisper に同梱の Silero VAD。取得は不要です |
| 要約の LLM | LLM の種類（下記）と、その種類ごとのカード |
| 字幕の翻訳 | 「字幕＋要約・翻訳」のとき、字幕を何で訳すかを選びます（[字幕の翻訳（PLaMo）](#字幕の翻訳plamo)） |
| 翻訳特化モデル（PLaMo） | llama.cpp の実行環境と、PLaMo 3 Translate の 2B・0.8B |
| 話者ラベル | `sherpa-onnx` パッケージ（起動スクリプトが入れます）と CAM++ モデル |

Qwen3-ASR は手動で準備します（[開発ガイド](development.md#追加の機能extras) を参照）。

### 3. 取得と確認

- **準備する** で、足りないファイルを取得します。取得するファイルは配布元の版・サイズ・ハッシュを固定しています（`yata/catalog.py`）。
  - 途中のファイルは隠しフォルダ `.yata-download` に置き、中断や失敗のあとも続きから再開します。ハッシュが一致してから所定の場所に移します。
  - すでにあるファイルは上書きしません。サイズが違うファイルがあれば、取得を止めて知らせます。
  - 取得の前に空き容量を確認します。失敗したときは、原因（ネットワーク、空き容量、破損、既存ファイル、書き込み権限、読み込めない）を表示します。
- **準備完了** になるのは、読み込みテストに通ってからです。テストでは、この PC の装置と精度でモデルを読み込み、2 秒の無音で 1 回動かします。要約モデルは 1 行の JSON に答え、翻訳モデルは 1 行を英語に訳します（「試訳」として表示）。
- テストの結果は `setup.json` に保存され、ファイルが変わらない間は有効です。**確認する** でテストをやり直せます。手で置いたモデルの場合は、配布元のハッシュとも比べます（読み込めるが内容が違うものは「別の版」、読み込めないものは「破損」と表示します）。

準備画面で選んだもの（使い方、モデルの保存先、音声認識のモデル、要約の LLM、字幕の翻訳方法、PLaMo のサイズ）は `setup.json` に保存されます。環境変数（`YATA_MODEL_ROOT`、`YATA_ASR_*`、`YATA_SPEAKER_MODEL_PATH` など）を設定している場合はそちらが優先され、準備画面では固定として表示されます。取り込み中のセッションは始めたときのエンジンのまま動き、変更は次の共有から反映されます。

## 要約の LLM

要約はどの LLM でも同じ仕組みで動きます。話題の判定と要約は JSON で受け取り、同じ方法で検証します。セッションは始めたときの LLM を使い続け、LLM を変えると新しいセッションから反映されます。LLM との通信は、この PC 内のアドレス（`127.0.0.1`、`localhost`、`::1`）に限り、プロキシもリダイレクトも使いません。

| 種類 | Yata がすること | モデル |
|---|---|---|
| 内蔵（llama.cpp） | ボタンを押すと、固定した llama.cpp b11800（Vulkan 版）と GGUF モデルを取得します。要約が必要なときだけ `llama-server` を `127.0.0.1` の空きポートで起動し（オフライン、Web UI なし、thinking なし）、30 分使わないか Yata を終了すると止めます。実行する装置は、NVIDIA GPU、ほかの単体 GPU、CPU の順に選びます | Qwen3-8B Q4_K_M（Ollama の `qwen3:8b` と同じ重み） |
| Ollama | `127.0.0.1:11434` に接続し、許可したモデルを Ollama 経由で取得します。Ollama 本体のインストールは利用者が公式サイトから行います | 許可リストのモデル |
| OpenAI 互換 API | 入力した URL（この PC 内のアドレスのみ）に `response_format: json_schema` で問い合わせます。対応していないサーバーには、スキーマをプロンプトに入れて問い合わせます | 入力したモデル 1 つ |
| Foundry Local | `foundry` コマンドがある場合だけ表示します。`foundry service status` でポートを調べ、サービスの起動とモデルの取得はボタンを押したときだけ行います | `qwen3-8b`、`mistral-nemo-12b-instruct`（PC に応じて CUDA・WebGPU・CPU 版） |

- まだ選んでいないときは、許可したモデルの入った Ollama が動いていれば Ollama を、そうでなければ内蔵を表示します。
- Ollama のカードに表示するモデルの保存先は、動いている Ollama が示すフォルダです。わからない場合は、Ollama が前回の起動時にログへ記録したフォルダ、`OLLAMA_MODELS`、`~/.ollama/models` の順に使います。
- 環境変数（`YATA_LLM_BACKEND`、`YATA_OPENAI_BASE_URL`、`YATA_OPENAI_MODEL`、`YATA_LLAMA_SERVER`、`YATA_LLAMA_DEVICE`）は画面の選択より優先されます。OpenAI 互換サーバーの API キーは `YATA_OPENAI_API_KEY` からだけ読み、保存も表示もしません。

## 字幕の翻訳（PLaMo）

**字幕＋翻訳** では、Preferred Networks の翻訳専用モデル **PLaMo 3 Translate** で字幕を訳します。要約モデルが重すぎる PC でも使えます。

- **モデル**：準備画面で 2 つのサイズから選びます。
  - **2B**（`pfnet/plamo-3-translate-2b-GGUF`、メモリ約 2 GB）：既定。
  - **0.8B**（`pfnet/plamo-3-translate-0.8b-GGUF`、メモリ約 0.8 GB）：CPU では約 3 倍速いですが、単位や意味がずれる行が増えます。
  - 手元の PLaMo 3 の GGUF ファイル（別の量子化など）も使えます。カードの **自分で用意した PLaMo 3 Translate（GGUF ファイル）** にフルパスを入れて保存すると、一覧に加わります。ファイルが存在し、GGUF の情報が `plamo3` のものだけを受け付けます。取得やハッシュの確認はしないので、使う前に **確認する** で読み込みテストをしてください。別のファイルに変えると、前のテスト結果は消えます。**指定を外す** で元に戻ります。
- **動かし方**：内蔵の LLM と同じ llama.cpp の実行環境を使い、専用の `llama-server` で動かします。必要なときに起動し、30 分使わないか Yata を終了すると止めます。
- **対応言語**：53 言語です（Yata の `zh` は PLaMo の `zh-hans`）。ポルトガル語には対応していないため、PLaMo で訳すときは選べません。
- **訳せなかったとき**：字幕はただの文字として扱い、指示として解釈しません。上限で途切れた訳は表示しません。何度か失敗した行は訳さずに残し、次の行から続けます。
- **ライセンス**：PLaMo Community License です。準備画面で取得する前に表示します。
  - 個人の利用と、学術を含む非商用の利用は無償です。
  - 仕事での利用は、利用者（または関連会社）の年間売上が 10 億円以下なら、PFN のフォームで登録すると無償です。10 億円を超える場合は、PFN との別の契約が必要です。
  - 訳文を公開するときは、PLaMo の出力であることを明示してください。

### 要約と一緒に使うとき

「字幕＋要約・翻訳」では、準備画面の **字幕の翻訳** で訳し方を選びます。

- **翻訳特化モデルを使用する**：PLaMo が 1 行ずつ速く訳し、要約の LLM に翻訳の負荷がかかりません。PLaMo が対応していない言語は要約の LLM が訳します。PLaMo の取得とメモリが別に必要です。選んだサイズが音声認識・要約モデルと一緒に GPU に収まらない見込みのときは、画面に注意が出ます。
- **要約 LLM と同じモデルを使用する**：要約の LLM が数行ずつ訳します。追加の取得もメモリも要らず、どの言語にも訳せますが、その LLM の速さに左右されます。

翻訳と要約は、セッションごとに 1 つの待ち行列を共有します。翻訳が先ですが、要約を書いている間は待ちます。訳し方を選ぶまでは、PLaMo が準備済みで、音声認識・要約・PLaMo の 3 つが GPU に収まる場合だけ PLaMo を使います（必要なメモリに 5 % の余裕を見て判定します。OpenAI 互換サーバーのモデルはサイズがわからないため、収まらないものとして扱います）。どちらで訳すかはセッションを始めるときにサーバーが決め、セッションの間は変わりません。

## 画面の使い方

画面は、**サイドバー**（セッションの一覧）、上部の **セッションバー**（開いているセッションと操作）、その下の作業領域に分かれています。

### サイドバー

- **新しいセッション** で開始画面を開きます。選んだ使い方に足りないものがあると、代わりに **この PC の準備** を開きます。
- 保存したセッションを日付ごと（今日、昨日、日付）に、新しい順で並べます。開始時刻・聞いた時間・話題の数を表示します。取り込み中は点が点滅し、取り消したり途中で止まったりしたセッションには「中断」が付きます。
- 検索欄で名前を絞り込めます。行をクリックすると開きます（サーバーを再起動したあとも開けます）。
- ごみ箱アイコン（マウスを重ねると表示）で終わったセッションを削除します。1 回目のクリックで確認になり、2 回目で削除します。取り込み中のセッションは先に止めてください。
- 下部には、LLM・音声認識・話者ラベル（Slack を有効にしていれば Slack も）の状態ランプと、診断ボタンがあります。
- 幅 960 px 未満では、サイドバーはメニューボタンで開くドロワーになります。

### 新しいセッション

1. 入力元（現在は「タブの音声」だけ）と、配信の言語（または自動）、要約の言語、字幕の翻訳先、要約のモデルを選びます。要約のモデルで **使わない（要約なし）** を選ぶと、字幕だけ、または PLaMo で訳した字幕だけを記録します。
2. 丸いボタンを押すと、Chrome の共有ダイアログが開きます。配信を流しているタブを選び、**タブの音声を含めて共有する** をオンにします。共有した時点でセッションが作られます（ダイアログを取り消すと何も作りません）。
3. 共有したタブはそのまま再生されます。Windows では、システム音声付きで画面全体を共有することもできます。

翻訳先を選んだのに PLaMo がまだ準備できていない場合は、足りないもの（llama.cpp の実行環境、モデル）を表示し、準備ができるまで開始を待ちます。

セッション名は入力しません。Chrome は共有したタブのタイトルや URL をページに渡さないため、名前は内容から付けます。最初は「タブ音声 11/04 10:15」のような名前で、最初の話題に名前が付くとその名前に、終了時には配信全体の名前に変わります。URL は、共有したページが Capture Handle API で自分のオリジンを公開している場合だけ入ります（YouTube など多くのサイトは公開していません）。

### セッションバー

- 状態、名前、開始日時と入力元、出典のリンク、聞いた時間の時計を表示します。
- ファイルのアイコン（**Markdown で書き出す**）で、取り込み中でも終了後でもセッションを書き出せます。
- 取り込み中は **終了して要約**（最後の音声を処理し、話題を閉じて要約し、全体のまとめを作る）と **×**（最後の処理をせずに取り消す。認識中の行は捨てます）が使えます。共有が止まった場合は **タブを共有** が出ます。
- 終わったセッションでは **続きを取り込む** で再開できます。新しい音声は同じ時間軸の続きに追加され（止めていた時間は数えません）、新しい話題として始まります。全体のまとめと名前は次に止めたときに書き直します。

### 波形と字幕

- 波形の上の行に、音声認識の時間・待ち行列・LLM・接続の状態（負荷が高いと黄色や赤になります）と、配信の言語・サンプルレート・入力レベルを表示します。
- 波形の下のタイムラインに、話題と、音声が届かなかった区間（赤い印）を表示します。話題をクリックするとそのカードへ移動します。
- 字幕は、話している途中の行が 1 文字ずつ表示され、話し終わると確定して上に流れます。話者のチップ（S1、S2…）に合わせて波形の色が変わります。
- PiP アイコンで、常に手前に表示される字幕の小窓を開けます（Chrome 116 以降）。

### 文字起こし・話題・話者

- **文字起こし**：すべての行を、時刻・言語・話者・訳文と一緒に表示します。話者での絞り込みと検索ができます。
- **話題**：進行中の話題を上に（仮の要約）、終わった話題をその下に表示します。終わった話題には、検証済みのポイント、重要な数値、根拠の引用数（クリックで元の行を表示）が付きます。要確認の文は黄色の縞で示します。更新アイコンで、今すぐ話題を判定できます。終わったセッションでは、全体のまとめを話題の上に表示します。
- **話者**：話者ごとの発言の割合を表示します。
- 幅の広い画面では、文字起こしと話題の間の仕切りをドラッグして（または矢印キーで）幅を変えられます。ダブルクリックで元に戻ります。幅はこのブラウザに保存されます。

### メモと書き出し

- **メモ**：話題の上にある、自分用のメモ欄です。入力が止まって少しすると（または欄から離れると）保存され、書き出しにも含まれます。時計のアイコンで、カーソルの位置にセッションの時刻（例：`[00:12:34] `）を入れます。最大 20,000 文字です。
- **Markdown で書き出す**：セッション名・開始日時・長さ・言語・要約モデル、メモ、全体のまとめ、話題ごとの要約（根拠の時刻付き）、話題ごとにまとめた全文（話者・訳文・音声が届かなかった区間付き）を 1 つのファイルにします。要確認の文は「省いた」とだけ書き、本文は書きません。文字起こしと LLM の文章は Markdown として解釈されないようにエスケープします。メモは書いたまま入れます。ファイル名は開始日時とセッション名から付けます。

### 表示言語とテーマ

- 画面の言語は日本語と英語です。既定では、ブラウザの言語設定（Chrome は OS の言語に従います）の中で先に見つかったほうを使い、どちらもなければ日本語にします。**設定 → 表示言語** で固定できます。サーバーのメッセージ、準備画面、書き出しの見出し、起動スクリプトのメッセージも同じ言語になります。
- 配信・要約・字幕の翻訳の言語は、セッションごとに選びます。
- PLaMo の利用条件と、古いセッションに保存済みのメッセージは日本語のままです。
- テーマは「ソフト」が既定で、「HUD」も選べます。切り替えスイッチは `YATA_FEATURE_THEME_SWITCH` を有効にしたときだけ表示されます（[機能トグル](development.md#機能トグル)）。

## 保存・再開・削除

- モデル、準備画面の設定、セッションは、OS ごとのデータフォルダに保存します（[README](../README.md#データとプライバシー) を参照）。`YATA_DATA_DIR` でデータフォルダを、`YATA_MODEL_ROOT` でモデルの保存先を変えられます。モデルの保存先は準備画面でも変えられます。
- セッションのファイルには、文字起こし・話題・要約・訳文・全体のまとめ・欠落区間・メモが入ります。音声、話している途中の字幕、診断情報、話者の特徴量は保存しません。
- セッションは取り込み中も自動で保存されます。サーバーが止まって中断したセッションは、あとから再開できます。そのとき送信中だった Slack のメッセージは、届いたかわからないため「失敗」と表示します。送り先を確認してから再送するか決めてください。
- 終わったセッションを削除すると、メモリと保存ファイルから消えます。書き出した Markdown は別のファイルなので残ります。

## Slack への送信（任意）

既定ではオフです。`YATA_FEATURE_SLACK` を有効にし、`YATA_SLACK_WEBHOOK_URL` に Incoming Webhook を設定したうえで、セッションごとに送信を選びます。

- 送るのは、検証済みの話題の要約と全体のまとめだけです。音声、文字起こしの行、要確認の文は送りません。
- 送信に失敗すると、再送ボタンを表示します。自動では再送しません。
- Webhook の URL は画面にも API にもログにも出しません。

## 制限

- メモリに置くセッションは最大 8 つです。終わったセッションはメモリから外し、開くときにファイルから読み込みます。1 つのセッションに入るのは、全体で最大 10,000 行・2 MiB の文字までです。
- 話者ラベルは、保存したセッションを読み込み直すと振り直されます。再起動の前後で同じ S1 が別の人を指すことがあります。ラベルは目安です。
- 音声認識と翻訳は間違えることがあります。歌詞や音楽では特に不正確です。CPU では、話し終わってから字幕が出ます。
- 検証に失敗した要約の文は、採用せずに要確認として表示します。自動の検証は、文の正しさを保証するものではありません。根拠の行を確認してください。
- デスクトップアプリの音声は、Chrome の画面共有でシステム音声を渡せる場合だけ取り込めます。Yata 独自の音声取り込みはありません。

手動でのモデルの配置、環境変数、Qwen3-ASR については [開発ガイド](development.md)、ハードウェアの選び方は [性能と測定方法](performance.md) を参照してください。
