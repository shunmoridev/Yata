# 構成とセキュリティ

[README に戻る](../README.md)

Yata は、FastAPI のプロセスが `127.0.0.1:8765` でブラウザ向けの画面を配信するローカルアプリです。音声の取り込みはブラウザの共有ダイアログから始まります。音声認識と、選んだ要約・翻訳の LLM は、この PC で動きます。操作と保存先は [使い方ガイド](usage.md)、設定とテストは [開発ガイド](development.md) を参照してください。

## 音声と推論の流れ

1. ページが音声の共有を求めます。AudioWorklet がモノラルの float32 PCM を作り、同じオリジンの WebSocket で送ります。各フレームには連番とサンプル位置が付いているので、途切れた区間を検出できます。
2. 送信待ちの音声は、最大 60 秒・12 MiB まで保持します。あふれた場合は古いフレームから捨て、その区間を欠落として表示します。届かなかった音声を、文字起こしできたかのように見せることはしません。
3. 音声を 16 kHz にリサンプリングします。faster-whisper に同梱の Silero VAD v6 が、間や発話の長さの上限で区切ります。音楽が流れ続けて VAD が発話として検出しない場合は、音量をもとに短い区間で区切って音声認識に渡します。歌詞の認識は話し声より不正確です。
4. 音声認識は、音声の受信や要約とは別のワーカーで動きます。通常の構成では、CUDA が使える GPU では whisper-large-v3-turbo、CPU では whisper-small（int8）を使います。Qwen3-ASR は Windows・Linux の CUDA 向けの追加の構成です。話者ラベルは別の特徴量モデルで、確定した発話をセッションごとに分類します。
5. 確定した字幕は、話題の処理に回ります。要約の LLM が話題の区切りと要約を提案します。新しい発話や間があると区切りを判定し、長すぎる話題は分割します。翻訳は読むための補助で、要約の根拠には使いません。

## 信頼できない入力と根拠の検証

聞き取った音声、字幕、タイトル、メモ、LLM の応答は、すべて信頼できないデータとして扱います。PC 上で実行するコマンドにはなりません。

- 要約の各ポイントが示す根拠は、その話題の元の字幕の行と照合します。
- 数値は、対応する言語の表記の違いをまたいで比べます。対応していない単位換算は認めません。重要な数値は根拠の行と一致する必要があります。
- 検証に失敗したポイントは、黙って採用せずに要確認として表示します。

これらの検証は、音声認識や要約が事実として正しいことを保証するものではありません。字幕が間違っていれば、要約もそれに沿って間違えます。話者ラベルも間違えることがあります。要約を使う前に、示された元の行を確認してください。翻訳に失敗した行は、訳をでっち上げずに失敗として残します。PLaMo に渡す字幕からは、特殊トークンの形をした文字列を取り除いてからプロンプトを組み立てます。

Markdown の書き出しでは、文字起こしと LLM の文章をエスケープします。利用者のメモは書いたまま入れます。

## ブラウザと API のアクセス制御

- 起動スクリプトはサービスを `127.0.0.1` で起動します。ローカルアプリであり、公開サーバーとして動かす方法はありません。
- HTTP リクエストは Host ヘッダーを検証し、許可したローカルのページ以外の Origin を拒否します。ページには、起動ごとのランダムなトークンを HttpOnly・SameSite=Strict の Cookie で渡します。API と音声の WebSocket はこのトークンを必要とし、WebSocket は Origin も検証します。
- Content Security Policy で、ページのスクリプト・素材・接続先をアプリ自身とローカルの WebSocket に限っています。API キーと Webhook の URL は、ページに返さず、書き出しにも含めません。
- LLM の接続先はループバックのアドレスだけを受け付け、プロキシを使わず、リダイレクトにも従いません。内蔵の llama.cpp サーバーは、ローカルのポートとオフラインモードで動きます。セッションは始めたときの LLM を使い続けます。取り込み中の音声共有は始めたときの音声認識エンジンを使い続け、次の共有から新しい設定が反映されます。

これらは Yata が公開しているインターフェースを制限するものです。PC にインストールされたネイティブライブラリや他のプログラムを隔離するものではなく、乗っ取られたローカルアカウントからは守れません。

## 保存するものと上限

- 生の音声はメモリ上にだけあり、録音しません。話している途中の字幕、診断用のサンプル、話者の特徴量はセッションに保存しません。
- 確定した文字起こし、要約、訳文、根拠、欠落区間、メモ、送信状態は、ローカルのセッションファイルに保存します。設定と読み込みテストの結果もローカルに保存します。保存先と削除については [使い方ガイド](usage.md#保存再開削除) を参照してください。
- セッションファイルは原子的に置き換えます。サーバーの停止で中断したセッションは「中断」と表示し、再開できます。送信中だった Slack のメッセージは「失敗」と表示し、自動では再送しません。
- メモリに置くセッションは最大 8 つで、終わったセッションはメモリから外してファイルから読み込み直せます。1 つのセッションは、全体で最大 10,000 行・2 MiB の文字、メモは 20,000 文字までです。セッションを読み込み直すと、話者ラベルは振り直されます。

## ダウンロードと依存ライブラリの通信

- モデルの準備は、準備画面で利用者がボタンを押したときだけ始まります。カタログには配布元のリビジョン、ファイルサイズ、ハッシュ（SHA-256 または Git の blob ID）を固定しています。
- ダウンロードは作業用フォルダに置いて再開でき、サイズの違う既存ファイルは上書きしません。ハッシュが一致してから所定の場所に移します。
- 準備画面が「準備完了」と表示するのは、この PC での読み込みと実行のテストに通ってからです。Ollama と Foundry Local は、それぞれ自分でモデルを取得します。
- Yata はローカルの音声認識モデルを `local_files_only=True` で開き、OpenTelemetry のエクスポーターを設定しません。ただし、これで依存ライブラリの通信を完全に防げるわけではありません。固定している faster-whisper の版では、手で置いたモデルフォルダに `tokenizer.json` がないと、Hugging Face から取得しようとすることがあります。モデルはファイルが揃った状態で置いてください。ネイティブライブラリのテレメトリや子プロセスの通信は、Yata では網羅的に調べたり遮断したりしていません。
- Python のテストには、`socket.getaddrinfo`、`socket.socket.connect`、`connect_ex` を包むガードがあります。拒否した呼び出しを記録し、テスト対象のコードが例外を握りつぶしてもテストを失敗させます。ただし、ネイティブ拡張・子プロセス・接続しない UDP・すべての名前解決 API は対象外で、`127.` で始まるかどうかの文字列判定なので一部の DNS 名も通します。回帰を見つける補助であり、外部通信を遮断する仕組みではありません。

意図している通信は、Python とパッケージのインストール、モデルと実行環境の準備、利用者が有効にした Slack への送信、利用者が開いたリンクです。外部への通信を一切許さない要件がある場合は、アプリの外で通信を制御し、使う依存ライブラリとビルドを個別に検証してください。このドキュメントはその要件を満たすことを保証するものではありません。
